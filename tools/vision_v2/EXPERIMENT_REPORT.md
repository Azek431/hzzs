## 海盐：与 AutoJs 多模板全区域扫描比较

对 `海盐客厅/Screoshkts` 的 68 张图片：

| 项目 | 结果 |
|---|---:|
| AutoJs 风格基线（5 个障碍模板分别全区域扫描） | 100.34 ms/帧 |
| LUT + 窄带 + 稀疏验证 + 轮廓贴边 | 6.13 ms/帧 |
| 相对加速 | 16.4× |
| 基线类别级正例 | 19 |
| 新算法覆盖 | 19/19 |
| 新算法额外检出 | 3 |

“额外检出”不能在没有人工标注时直接算作误报；人工接触表中多张看起来确实存在沙堡，但报告保守地不将其计为真阳性。

海盐轮廓的无标注边缘代理指标：

| 几何 | 轮廓点距 Canny 边缘 ≤2px 比例 | 平均最近边缘距离 |
|---|---:|---:|
| 最终贴边轮廓 | 0.651 | 3.17 px |
| 同一检测的矩形框 | 0.264 | 13.62 px |

Canny 只用于评估，生产检测不创建全帧边缘图。

## 已知空白

- 上传数据中没有 AutoJs 模式可确认的“大断崖/LARGE_WATER_PIT”正例。原型提供了从小水坑横向缩放得到的临时轮廓，标记为未验证，不应直接作为正式参数。
- 没有逐像素 mask，因此不能声称真实轮廓 IoU、边界 F-score 或绝对准确率。
- 规则得分尚未做概率校准。
- 当前每类只保留一个最佳候选，符合前方单障碍玩法；若画面可能同时存在多个同类障碍，需要加入一维 NMS 和固定容量候选数组。

## C++ 移植建议

核心数据结构建议固定容量、无每帧堆分配：

```cpp
struct RgbPoint {
    int16_t dx;
    int16_t dy;
    uint8_t r, g, b;
};

struct PatternProfile {
    ObjectId id;
    ScanBand band;
    std::array<RgbPoint, 7> points;
    uint8_t required_points;
    std::span<const Point16> canonical_contour;
};

struct Detection {
    ObjectId id;
    float score;
    RectF box;
    uint16_t contour_offset;
    uint8_t contour_count;
};
```

运行时建议：

1. RGBA 指针按 stride=2 扫窄带；
2. `uint16_t palette_lut[32768]` 返回类别位掩码；
3. 每类固定 32～64 个候选容量；
4. 候选进行 4-of-7、3×3 邻域颜色验证；
5. 放置最多 16～32 点的标准轮廓；
6. 沿法线 ±3 工作像素直接读取 RGB，选择局部对比最大的位置；
7. JNI 使用扁平 `float[]/short[]` 传轮廓，矩形由轮廓派生。

先实现标量版本并做 ABI/ASan 测试；只有真机 P95 不达标时再加入 NEON。不要先上全帧 Canny、GrabCut、模板相关或神经网络，因为它们会破坏当前低计算量目标。
